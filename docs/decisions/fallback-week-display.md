# fallback 주 화면 표시

구조가 맞는 fallback 주는, 복구 후 전체 하드 검증과 품질 게이트를 통과한 경우에만 `fallback_accepted`로 저장하고 수업 화면에 표시한다. 출처는 `fallback`으로 기록하며 모델 채택 결과로 대체할 수 있다(점수가 있거나 관리자가 수정한 날은 보존). 하드 오류가 남으면 `failed`로 저장하고 `class_weeks`로 동기화하지 않는다. 실패 시 화면은 기존 활성 주가 있으면 유지하고, 없으면 명시적 빈 상태를 보인다. 주 전체가 결정적 계획이면 코치 확인 대기로 둔다. 이 규칙은 P6(최종 검증 재연결)과 P2(결정적 표 수정)가 끝난 뒤에 켠다.

## 구현 전 선행 조건

- P6. `finalWeekReport.hard`가 최종 오류에 다시 연결되고, 헤드 셀 반영 뒤에 재검증이 돌아야 한다.
- P2. `deterministicGoalTable`이 모든 훈련일을 `lower_strength`로만 두지 않도록 고쳐져야 한다.

이 두 가지가 끝나기 전에는 위 저장 규칙을 켜지 않는다.

## 스위치

`FALLBACK_WEEK_DISPLAY`가 `"1"`일 때만 검증을 통과한 fallback 주를 active로 저장하고 수업 화면에 복사한다. 기본값은 꺼짐이다. P2가 남아 있으므로 기본은 계속 꺼 둔다. 꺼져 있으면 fallback 주는 failed와 같이 화면에 복사하지 않고, `generation_source`는 fallback으로 남긴다. 켜짐과 꺼짐을 둘 다 테스트한다.

## 미정 사항(품질 게이트의 최소 기준)

비워 둔다.
