# 회원 관리와 관리자 WOD 편집

생성 경로와 생성 flag는 바꾸지 않았다. `docs/generation-paths.md`는 그래서 고치지 않았다. 월간·주간·뼈대·세션·Head Coach·`evaluateWeek` 함수는 그대로다. 저장 직후 카탈로그 버전을 고정하는 한 줄과, 화면 진입 전에 상태·생성 상한을 보는 호출만 더했다.

검증은 2026-10-13 워크스페이스에서 했다. 운영 DB와 운영 주는 열지 않았다.

## 실행 결과

| 명령 | 결과 |
| --- | --- |
| `npx vitest run` | 82 files, 525 tests 통과 |
| `npx tsc --noEmit` | 통과 |
| `npm run build` | 통과 |

회원·WOD 테스트는 임시 DB와 주 `2099-01-05`만 사용했다. 피로 상한 문장만 있는 판정은 저장되고, 그 문장과 다른 하드 오류가 같이 있으면 저장되지 않는다. 빈 컨디셔닝으로 만든 주는 `evaluateWeek`가 거절하고, 그 판정으로는 저장하지 않는다. 단위를 넣거나 카탈로그 밖 동작을 넣으면 버전이 생기지 않는다. 원본 `programming_weeks.plan_json`은 수정 뒤에도 같다. 되돌리기는 새 버전이다.

임시 DB에서 브라우저로 확인했다. 대기 회원은 로그인 뒤 승인 화면에 남고 `/dashboard`도 그 화면으로 돌아간다. 관리자가 승인하면 상태가 활성이 된다. `2099-01-05` 주에서 `note_ko`를 저장하면 version 1 `original`과 version 2 `edit`가 생기고, 노트는 edition에만 있다. 원본 `plan_json`에는 그 노트가 없다.

## 동작

- 가입은 이름과 생년월일만 받는다. 만 14세 미만은 거절된다. 화면 가입은 `pending`이다. 기존 테스트가 부르는 프로필 없는 가입은 `active`로 둔다.
- 같은 주소의 가입은 1시간에 5회다. 여섯 번째는 429다.
- 관리자가 없으면 `FIRST_ADMIN_EMAIL`과 같은 주소가 관리자이자 `active`가 된다.
- 상태나 역할이 바뀌면 그 회원의 세션을 지운다. 마지막 관리자는 강등, 정지, 탈퇴가 안 된다.
- 탈퇴는 `docs/privacy-withdrawal.md`다.
- 회원 검색은 이름이다. 이름이 없는 기존 행은 이메일로도 찾는다.
- 칸은 `movement_id`, `quantity_option`만 고친다. 단위와 Rx는 카탈로그가 채운다. 자유 입력은 `note_ko`다.
- 칸 출처는 `model`, `head_coach`, `admin_edit`다. 그 주의 카탈로그 버전은 주가 만들어질 때 고정된다. 이 컬럼이 생기기 전의 주는 마이그레이션 시점 버전으로 채운다. 과거 카탈로그 파일은 없다.
- 회원별 새 주 생성은 기본 7일에 4회다. 이미 있는 수업 주는 횟수에 넣지 않는다.
- Next.js 15 미들웨어는 Edge라 SQLite를 열지 못한다. 모든 API 라우트가 요청마다 `guardMemberRequest`를 부르고, 생성 화면은 레이아웃이 상태를 본다.

## 미룸

카탈로그 편집 화면, `coach` 역할, 관리자 메모, 공지, 출석, 리더보드, 결제.

배포 절차는 `docs/deploy-member-mgmt.md`다. 이 작업은 병합과 배포를 하지 않았다.
