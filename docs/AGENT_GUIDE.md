# Strength Lab 작업 지침서 (모든 단계에 항상 적용)

## 문서
- 생성 경로·flag 분기·프롬프트 버전·fallback 조건을 바꾸면 같은 커밋에서 docs/generation-paths.md 를 갱신한다(flag 조합별 진입점·함수·프롬프트 버전·fallback 조건, 파일·조건식 근거).
- 단계 결과는 docs/<stage>-results.md(한국어)와 docs/<stage>-probe.json 에 남긴다.
- 실제 모델 프로브 결과와 모킹 테스트 결과를 구분해 적는다. 실행하지 않은 검증은 통과로 쓰지 않는다.

## 실행 환경
- 워크스페이스에서만 구현·검증한다. 합치기·배포·NAS·운영 DB·운영 flag는 사용자 승인 없이 하지 않는다.
- 실제 프로브는 scripts/plan-lab.ts, 2099 임시 DB만. 운영 주 2026-10-05 등 운영 데이터 사용 금지.
- 기본 모델은 gpt-5.4-nano다. 세션 생성만 `SESSION_MODEL_KEY`로 바꿀 수 있고 월간·헤드 코치는 nano에 남는다. MONTH_PLAN_MODEL_KEY 등 키·비밀번호 출력 금지.
- A1/A2 원본 로그는 실행별 고유 경로(gitignore)에 보존하고 커밋하지 않는다.
- 첫 모델 호출이 429 등 인프라 오류면 멈추고 보고한다.

## 원칙
- 5/3/1 고정 금지(여러 method 중 하나). 훈련 내용의 고정 요일 템플릿은 금지다. 기본 6일 수업의 요일 구성만 코드가 정한다. 월~토는 훈련이고 일요일만 휴식이다. 주간 코치는 월~토의 포커스와 강도 분배만 채운다. 리프트 계열과 존 2 하루는 `placeClassLifts`가 규칙으로 정한다. 요일 고정표가 아니다.
- AI가 판단하고 코드는 계산·검증한다. fallback은 성공이 아니다.
- 검증 기준·임계값(유사도 4 등)을 완화해 통과시키지 않는다. 피로 상한 문장만 경고이고 채택을 막지 않는다.
- 세션 코치(컨디셔닝, 스트렝스, 워밍업)는 칸별 카탈로그에서만 고른다. 하루 메트콘은 강도 4(Rx) 하나다. 강도 4는 작업량이 아니라 노력이고, 문구는 `RPE 8 안팎, 완주하되 마지막 구간이 힘든 정도`다. 프롬프트와 회원 화면이 같은 문구를 쓴다. 날짜별 무엇 위주·자극·시간대는 주간 계획을 따른다. 무거운 날은 중량을 올리고 반복을 제한하는 쪽을, 컨디셔닝 날은 지속 가능한 작업량을 앞에 둔다. 그 선호로 후보를 비우지 않는다. 캡·라운드·수량은 서버가 같은 페이스 식으로 미리 계산해 최소와 캡 안에 들어오는 번호만 준다. 스케일은 같은 응답의 번호다. 모델은 사다리의 쉬운 짝에서만 동작을 고르고, 수량·무게는 그 번호 안에 있다. 스케일 검사는 같은 형식·캡, 같은 동작 패턴, Rx보다 쉬운 기술 단계 또는 가벼운 무게, Rx 작업량의 0.6–0.85다. Rx 후보가 없으면 호출하지 않고 규칙 모순으로 남긴다. 스케일 후보가 없어도 Rx가 통과하면 그 날은 채택되고 스케일만 규칙 모순이다. 예상 완료 시간은 모델 출력이 아니고 서버 derived다. 코드는 고른 동작이나 숫자를 바꾸지 않는다. 고기술·고충격의 횟수 상한은 기존 수량 격자(거리 200·400·800, 횟수·칼로리 5의 배수, 초 30의 배수, 칸당 최대 8개)와 사다리 `risk_level`·`skill_level`이다. 새 상한을 더하지 않는다.
- 월간 목적은 `purpose_kind`와 `emphasis` enum이다. 문장은 코드 템플릿이고, 틀린 슬롯을 고정 문장으로 바꾸지 않는다.
- 헤드 REVISE는 현재 칸과 다른 enum id가 반영되고 `evaluateWeek` 하드 오류가 없을 때만 채택된다. 수정이 없으면 미해결이다.
- 4주 연속은 월간 코치 1회를 reuse하고, 잠긴 뼈대를 `evaluateWeek`에 넘긴다. 이전 주 구조와 실제는 다음 주 입력이다. 그 주의 피로·볼륨·완료는 월간 재사용 키에 넣지 않는다.
- 원인은 로그·코드 근거로만 확정한다. 추측은 추측이라고 쓴다.
- 최소 변경. 기존 기능 재작성 금지. Phase B·C 회귀 테스트를 매번 돌린다.
